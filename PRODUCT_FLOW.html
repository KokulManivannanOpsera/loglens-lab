LogLens lab · basics day

How AI + CI/CD + cloud work together

One product, two tracks that meet in production: ship the app (Git → CI → image → cloud) and run the brain (mock → LLM → RAG → eval → agents). Every tool from LEARNING.md appears below with its role.

Trust rule: diagnosis is always a draft. Humans approve any real-world side effect (PR comment, ticket, re-run). Eval + guards come before automation.

3. Every tool — role in the product

Green outline = already done in the lab (A0, A1, D0, D1).

AI / product brain

A0 · done

Mock diagnoser + fixtures

Fake “model” with rules. Same JSON shape as real LLM. Learn product without an API key.

A1 · done

LLM API · OpenAI

External model. System + user prompts. Returns structured diagnosis. Key in env.

A1b

Context window / truncation

Logs can exceed model desk size. Keep head+errors+tail so the failure line isn’t dropped.

A1c

Prompt injection defenses

Log text is untrusted. “Ignore rules / auto-approve” must not change privileges.

A2

RAG · runbooks

Retrieve known-failure docs, stuff into prompt, cite evidence. Grounded answers.

A2b

Embeddings · vector DB

Turn chunks into vectors; similarity search (+ keyword hybrid). Often pgvector.

A3

Eval suite

Golden logs → expected cause. Catches prompt regressions. Runs inside CI.

A3b

AI observability

Latency, token use, ungrounded rate, prompt version — without leaking secrets.

A3c

Human feedback

Thumbs up/down → grow the eval set. Product learning loop.

A4

Tools · light agent

Model may call search/grep. Loop with max steps. Optional LangGraph later.

A4b

Agent safety · guardrails

Allowlists, shadow mode, audit trail, approve before any write.

A5

Streaming

Tokens to UI as they arrive; cancel mid-flight.

A6

Memory · cache

Store diagnosis history; cache same log hash to save cost.

A7

Multi-model routing

Cheap model triage → strong model for hard cases; provider fallback.

A8 optional

Light fine-tune

Only if RAG+prompts plateau. Small adapter — not train GPT from scratch.

Runtime libs

Next.js · React · Node

UI + API in one app. fetch to OpenAI (no SDK required in A1).

CI/CD · ship path

D0 · done

Local run · health

npm run dev, /api/health. Proves process is alive.

D1 · done

Git · GitHub · PR

History, branches, review. main stays known-good.

D2

Dockerfile

Package app + Node into an image. Same binary everywhere.

D3

docker compose

One command to start app (+ later DB) with networks/volumes.

D4

GitHub Actions CI

On every PR: lint, test, AI eval, build. Red check = no merge.

D10

Registry · scan

Push image:git-sha to GHCR/ECR. Trivy/Grype/Dependabot for CVEs.

D9

CD · promote

Same artifact → staging → prod. Rollback, approvals, feature flags.

Also

Jenkins / GitLab CI / Argo / Flux

Same CI/CD jobs; GitOps syncs cluster from Git (after K8s).

Cloud · where it runs

D5

PaaS · Railway / Render / Fly

Fast public HTTPS URL. Learn deploy before raw AWS.

D6

Secrets

LLM key + DB URL in host/CI secrets — never git. Vault / AWS SM / platform env.

D7

Managed Postgres

History + later vectors (pgvector). RDS / Cloud SQL / PaaS add-on.

D8

Platform observability

Logs, metrics, traces, alerts (CloudWatch / Datadog / etc.).

D11

Terraform / Pulumi

Declare cloud resources as code instead of only clicking consoles.

D12

Kubernetes

Orchestrate many containers. Local kind/minikube first; EKS/GKE later.

D13

Cloud IAM

Least privilege: deploy role ≠ runtime role. No root keys on laptops.

Building blocks

Compute · LB · DNS · VPC

EC2/ECS/Cloud Run, load balancer + TLS, Route53-style DNS, private DB network.

4. How the two tracks meet

CI needs AI eval

A3 golden tests run in D4 so a bad prompt can’t merge.

LLM needs secrets

A1 key only works safely with D6 in staging/prod.

RAG needs data store

A2b vectors usually live in D7 Postgres.

Agents need observe + HITL

A4 tools + A4b approve + D8/A3b logs so you can debug 2am failures.
